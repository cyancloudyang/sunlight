## 意图与动机

把 macOS 桌面变成一张大桌布：窗口摆放在桌布的不同区域，靠物理位置记忆窗口（AI coding agent 在右上、三个浏览器窗口在左上、两三个 Finder 在下中、终端在右下）。像即时策略游戏一样对地图快捷缩放、移动视角，点击某个窗口则聚焦为真实窗口自然充满整个显示器。

为什么：窗口堆叠如披萨盒，位置记忆无处安放；现有平铺/分屏工具把窗口锁在显示器网格里，没有"空间"可言。

硬性约束（用户明确提出）：
- 不关闭 SIP，不做任何 SIP 相关改动。
- CPU、GPU、内存占用尽量低。
- 在 Sunlight fork（MIT）基础上改造开发，经 GitHub（cyancloudyang/sunlight）进行。

## 目标（v1）

- 地图模式：全屏画布，按桌布坐标显示所有被管理窗口的快照；窗口位置即布局。
- RTS 式相机：触控板平移/缩放、指向缩放、相机书签热键（保存/跳转视角）。
- 聚焦/返回：点击地图上的窗口 → 真实窗口充满显示器并激活；热键返回地图，窗口回到原位。
- 布局持久化：窗口世界坐标、相机、书签跨启动/重启恢复（按 app+标题匹配）。
- 新窗口自动纳入地图，落在当前视野中心；地图上拖拽摆放；可选网格吸附。
- 资源目标：地图静止时 CPU ≈ 0；无常驻捕获流；典型内存 < 100MB；聚焦模式开销 ≈ 0（画布隐藏，只剩热键监听）。

## 非目标（v1 明确不做）

- 地图上窗口内容的实时更新（用户已选快照路线；视频/动画在地图上是定格的）。
- 缩放状态下直接在被缩放的窗口里打字点击（聚焦后才操作真实窗口）。
- 多显示器（v1 只管主屏）。
- takeover 模式：不改 Dock/Finder/系统手势等任何系统偏好；不做登录项（后续可选）。
- 桌面文件/小组件搬上地图、PiP、自动平铺、Stage Manager 集成。

## 反目标（即使技术上行得通也不接受）

- 任何 SIP 改动、任何注入系统进程的代码。
- 任何"必须"的私有 API（私有 API 只允许作为有公开兜底的可选项）。
- 常驻捕获流（SCK stream / CGDisplayStream 一律不用）。
- 空闲时的后台 CPU 消耗。

## 约束

- macOS 15+，Apple Silicon；目标机器：MacBook Air M2，macOS 27.2。
- 只需两个权限：辅助功能（移动/缩放/激活窗口、事件 tap）、屏幕录制（窗口快照）。
- 许可证边界：Sunlight（MIT）、orcv（MIT）可以改编代码并署名；canvasWM、minfwm **无许可证**，只借鉴思路与数学模型，不复制其代码。
- 参考项目：Sunlight（handoff 模型、捕获 LOD 策略、布局持久化匹配策略）、canvasWM（视口/世界坐标数学、AX 窗口匹配）、minfwm（"绝不用 AX resize 模拟缩放"的教训、远距降级思路）、orcv（本路线不用其虚拟屏，但其权限引导可参考）。

## 方案对比（Approaches）

| 方案 | 原理 | 代价 | 结论 |
|---|---|---|---|
| A 单流全活 | 一块大 CGVirtualDisplay 停所有窗口 + 一条 CGDisplayStream/IOSurface 捕获 | 地图永远新鲜；内存 150–300MB，内容动画时持续开销 | 未选 |
| **B 快照地图** | 真窗口留在原桌面；地图是快照纹理；AX 聚焦 handoff | 地图内容定格；资源绝对下限 | **用户已选（最省）** |
| C 混合 LOD | 近 1:1 窗口流式、远处快照（Sunlight demo） | 多流内存、实现最复杂 | 未选 |

选 B 的理由：用户把"三低"置于地图实时性之上。B 还有一个免费红利：地图遮罩用**不透明**全屏窗口，WindowServer 会把后方真实窗口标记为遮挡，应用自动停绘——停放窗口自身的 CPU/GPU 开销归零（Sunlight 为了活流刻意非透明，我们不需要）。

## 架构

桌布是**纯虚拟坐标系**：每个被管理窗口持有一个 worldRect（桌布上的位置+尺寸）。真实窗口留在物理桌面上不动；地图上拖拽、相机平移缩放只改元数据/纹理变换，零 AX 调用。聚焦时真实窗口 AX 移到主屏充满 visibleFrame（菜单栏下），与桌布坐标无关——这正是用户要的"自然充满整个显示器"。

部件：

1. **WindowRegistry**：CGWindowList 轮询（2s）+ AXObserver（创建/关闭/标题变化）。窗口身份：存活期用 CGWindowID；重启后用 app bundleID + 标题匹配（Sunlight 策略）。过滤：normal level、排除自身、排除桌面元素。
2. **LayoutStore**：worldRect、相机、书签 → `~/Library/Application Support/Tablecloth/Layout.json`，防抖保存；启动时恢复匹配。
3. **SnapshotStore**：每窗一张纹理，最长边 ≤ 1024px（可配）约束内存。一次性捕获：SCScreenshotManager 优先，CGWindowListCreateImage 兜底（均公开、SIP 安全；私有 SLSHWCaptureWindowList 仅作可选加速，可缺席）。刷新策略：进入地图时全量刷新可见窗口；相机停稳时刷新可见窗口；之后每秒轮换 1 张（可关闭）；聚焦返回时立即刷新该窗。锁屏/睡眠/地图隐藏时完全不捕获。
4. **CanvasWindow**：不透明全屏 NSWindow（normal level），CALayer 树绘制快照纹理，相机做 world→screen 变换。地图隐藏时 orderOut，零开销。
5. **CameraController**：双指滚动平移、捏合/⌥滚轮围绕指针缩放、空拖平移、WASD/方向键平移、Space 全景；小地图（右下角，点击/拖动跳视角、Fit 全景）；书签 1–9 跳转 / ⌃1–9 保存；easing 动画（长距离走 van Wijk–Nuij 弧线）。手势只作用于画布自身（key window），不改系统手势设置。
6. **Handoff（用户已选：平滑缩放动画）**：点击窗口 → 该窗新鲜截图 → 快照层从地图 worldRect 平滑放大飞至屏幕矩形（相机飞行/层动画），与此同时真窗口在动画背后 AX move/resize 到主屏 visibleFrame 并激活 → 动画结束交叉淡入真窗口。返回（F3/Mission Control 键或自定义热键）→ 真窗口截图 → 快照层从屏幕缩小飞回地图原位，真窗口 AX 恢复聚焦前 frame → 交叉淡入地图。验收口径：飞行平滑、无黑帧/闪烁/露出桌面；内容重排与清晰度变化由结尾交叉淡入掩蔽（resize 改变长宽比必然重排，这是快照路线的固有边界）。绝不用 AX resize 做"假缩放"（minfwm 教训：会触发应用重新布局）；resize 只发生在真实聚焦时。
7. **Hotkeys**：CGEvent tap 拦截 Mission Control 键（keycode 160）作为地图/聚焦切换；备选自定义全局热键（Secure Keyboard Entry 环境下 tap 受限时的退路）。地图内的点击/拖拽由画布视图自身处理。
8. **MenuBar**：菜单栏图标：地图开关、刷新间隔、网格吸附开关、退出。无 Dock 图标。

资源画像：
- 地图静止：纯 GPU 纹理合成（约 10 张纹理），CPU ≈ 0。
- 捕获：每秒至多 1 次一次性截图（约 12–30ms），可关。
- 聚焦模式：画布隐藏，仅事件 tap 监听。
- 内存：10 窗 × 1–4MB 纹理 + 应用基线 ≈ 50–100MB。

边界情况：
- 应用钳制 AX move/resize → 接受实际落点尺寸，不重试死循环。
- 窗口关闭/最小化/应用隐藏 → 地图上保留虚线占位与位置，恢复后回来。
- 其他 Space 的窗口捕获失败 → 占位卡片（app 图标+标题），点击时先切 Space 再聚焦（v1 可仅激活应用让系统切换）。
- 权限未授予 → 首次启动引导页（两个权限，可参考 orcv 的引导）。
- 地图激活时新窗口出现在当前视野中心，带短暂高亮。

## 已定的实现默认值（实现者/我的决定，用户可否决）

- 新纳入窗口的初始 worldRect = 其当前物理 frame（首次启动时地图就是真实桌面的 1:1 镜像，之后随拖拽分化）。
- 每秒轮换刷新**默认关闭**（与"最省"一致）；进入地图/相机停稳时的全量刷新保留。
- 全屏窗口与其他 Space 的窗口：地图上占位卡片，点击时激活应用让系统切换。
- 同 app 同标题的多窗口：确定性消歧（按存活期 windowID 顺序/最近使用），重启后尽力匹配。
- 菜单栏与 Dock 保持可见可用（画布 normal level，不覆盖菜单栏）。
- 地图失焦（其他应用被激活）时自动隐藏，热键随时召回——地图是"召唤式概览"，类似 Mission Control 的心智模型。

## 游戏化交互与视效（2026-11-10 用户追加：RTS 游戏直觉）

用户指示：整体操作逻辑参考游戏界面——缩放像空中摄像机拉远/拉近，窗口选择像游戏里选择战斗单位；要让人轻而易举知道怎么操作、直观理解动作与效果，并有视效动效。以下为实现者定的默认值（用户可否决）。

### 相机 = 空中摄像机

- 滚轮/捏合**围绕指针**缩放：指针下的世界点保持不动——摄像机朝你看着的地方下降/上升（上游已实现）。
- 长距离视角移动（书签跳转、聚焦、返回）走 **van Wijk–Nuij 弧线**：先拉远再拉近，读作"飞过去"而非"刷一下"（上游 `CameraPath` 已实现，全部复用它）。
- 平移：触控板双指（惯性）、空白处拖拽（抓取手型）、**WASD/方向键**（新增）；**Space = 全景**（回到基地心智）。
- 缩放有 min/max 边界，到界软弹簧回弹（上游 spring 已有）。
- **小地图**：右下角，视口框实时跟随，点击/拖动瞬移相机，Fit 按钮全景（上游 `MinimapPanel` 已有，默认开启）。直接服务"位置记忆"： terminal 在右下角？瞥一眼小地图就飞过去。
- **缩放读数**：缩放时短暂浮现百分比 pill（上游 `hudZoom` 已有，默认开启）。

### 窗口 = 战斗单位

- **悬停 = 预选**：发光边框（上游已有）+ 微微上浮（阴影加深，~120ms CA 动画）+ 名称牌（app 图标+标题，上游 label/pill 体系已有，悬停必现）。光标变指向手。
- **单击 = 命令**：聚焦该窗（俯冲进入，见 Handoff）。Return 键进入悬停窗口（上游已有）。
- **远距兵牌**：zoom < 0.35 时快照上叠 app 图标+标题横幅——远处的"单位"变成可辨认的兵牌，任何缩放下都知道那是谁（纯文本/图标层，零捕获成本）。
- **新窗口入场**：落在当前视野中心，弹入 + 光环脉冲一次（单位出生；上游 `noteArrived` 钩子已有）。
- **返回落点**：刚离开的窗口带一圈渐隐选中环（RTS 选中圈，"你在这"）。
- **拖拽摆放**：拖动中卡片阴影加深（被"举起"）；网格吸附开启时显示网格点（上游 `gridSizes`/对齐引导已有）。
- 光标三态：空白=张开手、拖拽中=抓取手、窗口上=指向手。

### 书签（StarCraft 式）

- 地图激活时：**1–9 跳转**书签，**⌃1–9 保存**书签（画布是 key window，数字键无打字冲突）。
- 保存时 toast"书签 N 已保存"（上游 canvas toast 已有）；跳转走弧线飞行，飞行本身就是反馈。
- 书签随布局持久化（`Layout` 增加可选 `bookmarks` 字段，旧文件兼容解码）。

### 可发现性

- 底部提示条（前 5 次进入地图显示，之后淡出，菜单可重看）："滚轮缩放 · 拖拽平移 · 点击聚焦 · F3 返回 · 1–9 书签"。
- 首次启动引导沿用上游 Tutorial/GestureGuide（带动画手势示意），内容去掉 live windows 升级引导。

### 视效清单（全部事件驱动 CA 动画，无渲染循环，符合三低）

1. 悬停发光边框 + 上浮阴影；2. 聚焦俯冲飞行 + 末端交叉淡入；3. 返回拉升 + 选中环脉冲；4. 新窗口弹入脉冲；5. 拖拽举起 + 网格点；6. 缩放读数 pill（已有）；7. 书签 toast（已有）；8. 小地图视口框（已有）。

### 上游已有、直接复用的系统

`MinimapPanel`（小地图）、`hudZoom`（缩放读数）、`WindowProxy.hovered`（悬停边框/控制钮）、label/pill（名称牌）、canvas toast、`CameraPath`（van Wijk 弧线）、`GestureGuide`/Tutorial（手势引导）、`Layouts`（布局持久化：bundleID+标题+windowID 匹配、跨启动记忆）、`NewWindowSpot`（新窗口落在视野内）、`onSettle`（相机停稳钩子）、`handingOff` 标志。
